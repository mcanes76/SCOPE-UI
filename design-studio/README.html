Build the shell together.

A fifteen-minute workshop and shell-only visual editor built around the existing Electric Glass mockup. All four simulated applications run inside the original engine. The Studio changes presentation; application stores, forms, connectivity models and operational behavior remain engine-owned.

Component Styles: semantic controls

Advanced Component Styles now resolves family, palette, global/category, application and individual styles with effective values and inheritance sources. Pick an eligible control to highlight it and edit its appearance without executing the action; click Exit Selection or Escape to leave. Guided controls remain shape, border style and control sizing only.

Six presets and grouped geometry, appearance, typography, hover/focus/pressed/selected/disabled/loading controls are provided. Reset property, Reset to Inherited, Reset Component and Reset All Overrides are undoable. Presets do not change action colors; intentional fill changes show identity/contrast warnings. Optional gradients keep a solid fallback.

Canonical IDs include application.blos.button.join, application.blos.button.create and shell.navigation.button.blos. Repeating rows use entity keys such as application.blos.button.join.node.n02, never a DOM index. Unambiguous old main-action aliases still work; ambiguous positional styles stay in JSON with a warning until explicitly rebound. Optional params.json componentStyles provides inherited defaults. All state and export paths use the same compiler.

Customer edition: double-click offline

Copy or extract dist/SCOPE-Design-Studio.html and double-click it in Edge or Chrome. This single file contains the complete Studio, all 31 presets, engine, Earth texture, logos and help. Customers need no server, installation, launcher or internet. The UI, editing modes, candidates, notes and exports use the same source implementation as the development edition.

python -m http.server 8080 --bind 127.0.0.1

Browser file:// access does not support the modular development entry; use the generated customer edition for direct-file launch. The exported standalone HTML can be opened directly.

Guided workshop / 15 minutes

  1. Navigation / 3 minutes. Choose Aperture, Mosaic, Portal or Command Deck. Details start hidden so the customer evaluates the shell first.
  2. Material / 2 minutes. Try the existing material treatments. Electric Glass is the existing White Trim treatment; Frosted White is the current Prism material, provided as an explicit discoverable alias. These aliases do not replace any engine look.
  3. Colors & edges / 3 minutes. Customize decorative colors, borders, radius, opacity and blur. Semantic success, error, warning, information and configuration controls retain engine colors.
  4. Type & density / 2 minutes. Set an installed font family, sizes, weight, density and spacing.
  5. Layout / 2 minutes. Choose shell-native or side-by-side arrangement. Command Deck has bounded navigation/context widths. Each other navigation model keeps its own organization.
  6. Final review / 3 minutes. Present with application details visible. Browser fullscreen is requested when permitted; the full available viewport is used otherwise. Return to Studio retains every selection.

Back, Next and the six step buttons let you revisit any decision. Record optional customer comments per step. Switch to Advanced Editor at any time without losing the design. Escape returns from presentation when the page receives the key; the Return to Studio button is always available.

Advanced editing and ownership

The left tree selects shell, header, branding, navigation, workspace, context rail or footer. Clicking shell chrome selects the same regions. The center is the actual mockup in an iframe. The right inspector applies immediate local overrides; Apply to Selected confirms the current live edit. Apply Globally promotes the selected region's edited colors, material and spacing to compatible shell containers and clears competing local values for those properties. Dimensions and visibility stay local. Reset to Theme Default removes that region's local overrides; current global overrides still apply.

Application behavior and structure remain protected from editing. Forms, tables, charts, globe cameras and operational controls remain interactive in the preview when details are shown. Their appearance can be selected through the explicit component-style picker; functional structure and event handlers remain protected. Global typography may be inherited by application content. Appearance changes do not reinitialize application DOM or stores.

Use preview scaling to evaluate wider console layouts within the editor. At native preview widths above 1250px, Command Deck exposes draggable rail separators with keyboard Left/Right adjustment. Sliders remain available at smaller sizes. Navigation is constrained to 140–280px; context to 180–360px. Context moves below the workspace at the engine's responsive breakpoint; narrow mobile navigation remains stacked. Primary navigation, branding and workspace cannot be hidden. Optional header, footer and context can be hidden.

History, checkpoints and persistence

Undo and Redo track design changes only, coalescing continuous control edits. Application operations and application switching do not enter design history. Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z work when focus is outside form controls. The last 100 design changes are retained.

Baseline is the loaded initial design. Save Candidate A, B or C, restore any checkpoint, or open Compare checkpoints for two independent side-by-side engine previews. Comparison starts fresh simulations with details hidden to emphasize shell differences. Checkpoints are held in memory for this session. Export each candidate as JSON to retain it across reloads; import then save it into the desired slot.

Import and export

  • Design JSON: complete versioned design and per-step notes. Import validates field names, IDs, color formats, finite numbers, fonts and protected regions. Dimensions are clamped to safe bounds. Files above 100KB and unknown versions are rejected without modifying the current design.
  • CSS overrides: selected shell tokens and local overrides. This is an override stylesheet, to be loaded after mockups/styles.css with existing engine markup, the documented engine look and body data-scope-design="true". Navigation and application behavior remain JavaScript-owned.
  • Standalone mockup: one HTML file embedding the original application code and Earth texture, complete baseline CSS, shared compiler, shell runtime, design, branding configuration, configured logo and SVG fallback. It opens independently of the Studio and shows details. JSON fetching and Studio loading are disabled in this export. Simulation data starts fresh; customer operational edits are intentionally not saved.
  • Decision summary: readable HTML settings and notes, full design JSON, plus Print / Save PDF.

Preview protocol

Messages use namespace scope-design-studio, version 1 and a randomly generated per-frame channel. Both endpoints verify exact origin, source window and channel. Offline previews use sandboxed srcdoc with no same-origin permission; opaque destinations require wildcard targetOrigin while exact source, expected origin and per-frame channel checks remain enforced. The preview accepts only configure, with a validated design, trusted preset list and explicit options for application selection, region selection and presentation. The engine reports ready, applied, selection, application, resize and error. No arbitrary CSS, selector, script or application-store mutation is accepted from the inspector.

Offline resources and runtime

offline.js replaces resource acquisition only when the generated embedded payload is present. Previews, comparison frames, Help, PNG/SVG fallback, imports and all downloads require no file fetches. embedded-windows.js supplies local HTML Blob windows with the same engine and independent sessions. CSS export shares the effective preset-token resolver with the preview, including all newer Electric Glass schemes.

The saved example scope-design.json is not automatically loaded; the current repository example has an extra closing brace and is rejected by strict JSON import. It is left unchanged. Startup uses the valid design-config.json.

Known limits and future work

Shell/navigation changes use the engine's existing rerender behavior. Shared model stores and per-slot application view maps survive; DOM focus, transient scroll, open dialogs and uncommitted DOM-only text can reset when moving between host slots. Styling edits alone preserve the DOM. Separate pop-up windows remain independent engine sessions, as in the original mockup. The standalone export preserves their existing browser-dependent behavior.

The Studio is session-based and single-user; collaborative use means a presenter and customer working together. No backend, autosave, account, remote collaboration or production stack integration is included. Fonts depend on what is installed. CSS backdrop blur and color-mix require a current browser. The model constraints cannot guarantee ideal ergonomics for every combination; check at the target resolution and viewing distance.

Potential future work: durable project storage, candidate bundles, target-display presets, browser screenshot regression coverage, and integration against real application embedding contracts.
