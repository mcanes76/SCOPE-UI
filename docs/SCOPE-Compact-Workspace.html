SCOPE Compact Workspace and Window Controls

Authorized change on feature/scope-app-integration, based on b6b0288. The initial working tree was clean. Phase 1 and Phase 3 remain intact, and Phase 2 Visual Families remains reverted. No application-owned interface, theme preset or design schema changes are introduced.

Diagnosis and scroll ownership

The generated design CSS gives .shell a minimum height of calc(100vh - 4px), while the Workspace Manager toolbar is a preceding sibling. Their combined heights exceed the viewport even if an application would fit. Classic split/stacked panes also previously forced a minimum of at least 520px, and the managed stage used an independent clamp(280px,calc(100dvh - 260px),820px) estimate. Neither accounted for actual toolbar wrapping, shell headers, footers, padding, navigation or task rows. The geometry model correctly fitted windows to the stage, but the stage could itself extend beyond the visible page.

The shell now has a bounded viewport flex chain: body, exploration panel, theme, workspace, shell, navigation host, managed canvas and stage. Flexible containers have a zero minimum height. Fixed shell chrome participates in normal flow, so its actual height is deducted automatically. The new rules outrank the generated shell minimum without changing the existing CSS compiler or design document. The visual viewport height is refreshed on browser resize; stage ResizeObserver and the existing fit action constrain window geometry. No application DOM is measured or rewritten for sizing.

Controls and space

Managed title bars keep the application name, Minimize, one Maximize/Restore command and Close visible. Dock Left, Dock Right and the single centralized Pop Out command are in a native disclosure menu. Labels identify the application; native Enter/Space and Tab work, with Arrow keys, Home/End, Escape and focus restoration added for the open disclosure. Menus close after an action or outside click. A docked window exposes Restore instead of an additional Maximize button.

The launch row replaces four application buttons with Open App and moves Cascade, Tile and Reset Workspace into Layout. All capabilities remain. Task buttons scroll horizontally when needed rather than creating more vertical rows. In Aperture, the navigation dock participates in flow instead of reserving a fixed 100px bottom region. Redundant shell-owned Deck/Portal current-application headings are hidden only in managed mode; per-window names remain. Application-owned headers are untouched.

Normal title-bar commands fall from six visible command buttons to three plus the overflow trigger. Launch commands fall from seven persistent buttons to two controls. Nominal single-row stylesheet budgets decrease by 14px for the operator toolbar, 12px for the launch row and 16px for the task row (42px combined, excluding borders, font-dependent growth, overrides and wrapped rows). These are CSS budget comparisons, not native rendered measurements.

They prove geometry and runtime behavior against explicit available bounds; they do not measure actual browser scrollHeight, native text metrics, scrollbar rendering or visual clipping.

No new theme family, operator panel, dependency, adapter behavior, schema field or application instance is added. No automatic merge or push is performed.
