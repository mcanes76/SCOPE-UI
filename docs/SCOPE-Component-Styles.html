SCOPE / COMPONENT STYLES

Appearance without changing application behavior

The editor extends the synchronized source, reusing DesignStore, preview messaging, history, candidates and export compilation. Application models and operational handlers remain unchanged.

Guided and Advanced

Guided Typography exposes three component controls: global shape, border style, and Compact / Comfortable / Spacious sizing. Advanced → Component Styles exposes scope, owner/category, six presets and grouped properties. Each property displays its effective value, inheritance source, overridden status and inherited value.

Presets: Square / Industrial; Slightly Rounded / Professional; Soft Rounded / Modern; Capsule / Pill; Flat / Minimal; Raised / Dimensional. These change geometry/elevation rather than semantic colors. Family changes retain intentional overrides.

IDs use application IDs, action names and explicit entity keys rather than DOM indexes, labels or host slots. Main Join and node-row Join have different IDs. A conceptual control retains its style across single/split/detached hosts.

Pick Component reveals application details and enters capture selection mode. The selection click is intercepted before the application action, and the selected component is highlighted and named in the inspector. Click Exit Selection or press Escape, including inside the preview iframe, to exit. Ordinary clicks continue to operate the demos. Dialog/menu buttons are annotated when rendered.

Inheritance

Family → Palette → Global component style → Application-specific style → Individual override. The retained classes scope refines global categories. Broad button styles precede semantic/category styles independent of JSON key order. Parameter defaults are inherited at the same scope, with explicit design values taking precedence there.

ScopeVisuals.resolveStyle reports values, provenance and warnings. The shared CSS compiler uses constrained component variables and equalized selector specificity so lower-scope selectors cannot outrank individual overrides accidentally. Variables reset on each button to prevent header/panel colors leaking into nested controls. A higher-scope radius resets inherited corners; explicit corners in that style then refine it.

Known enums, hex colors and finite bounded dimensions are validated. Arbitrary CSS, URL values and scripts are rejected. Legacy radius 50 still represents pill; other numeric radii clamp to 24px. Background opacity has a 20% lower bound. Loading appearance follows aria-busy/data-loading without starting or completing an operation.

Join remains green, Leave red, Warning yellow and Create/Update purple by default across families. Geometry changes do not alter fills. Explicit color overrides produce identity guidance. Estimated contrast warnings cover states/gradient endpoints and opacity over the workspace; actual composited browser contrast still needs review.

Resets and persistence

  • Reset property: removes one property from the selected block.
  • Reset to Inherited: removes that block.
  • Reset Component: clears the selected semantic instance and recognized aliases; in class/global scope clears that selected block.
  • Reset All Overrides: removes design component overrides, retaining imported defaults and other design settings.

Resets/presets participate in Undo/Redo. Continuous changes coalesce by target and property. Candidates, mode changes, Design JSON, CSS, Final, operator HTML and folder ZIP retain the same settings. Exports style actual controls through the shared annotation/compiler path.

Configuration and compatibility

See component-styles.schema.json, params.schema.json and params.example.json. Design schema 1 keeps existing scopes. Parameter schema 2 adds optional componentStyles. Old files migrate with inherited defaults.

{
  "schemaVersion": 2,
  "buttonGeometry": "inherit",
  "componentStyles": {
    "global": { "buttons": { "radius": 4, "height": 44 } },
    "classes": {}, "applications": {},
    "instances": {
      "application.blos.button.join": {
        "radius": 0, "borderWidth": 2, "border": "#008C3A"
      },
      "application.blos.button.create": { "radius": 50 }
    }
  }
}

Unambiguous legacy IDs such as blos:group-join:0 resolve to canonical main-action IDs and are promoted when edited. Ambiguous positional IDs remain in JSON and produce inspector warnings; they are not rebound to arbitrary rows. Select the intended semantic control and reapply them safely.
