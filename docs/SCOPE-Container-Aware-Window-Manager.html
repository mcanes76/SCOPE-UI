Phase B: Container-Aware Window Manager Sizing

Implemented in 1433d40 and corrected in 91b7e59. Phase B covers Window Manager measurement and geometry in the Studio and standalone prototypes. The later Context Panel and Studio preview changes build on this implementation. The Compact Workspace and Display Map-Centric Layout experiments were reverted.

Host measurement

The managed stage no longer uses 100dvh - 260px. In a browser, its actual top edge and width are measured with DOM geometry. The sizing pass walks shell-owned ancestors, accounting for normal-flow siblings below the stage, their margins, parent padding/borders, visible scrollport/declared height constraints and the actual viewport boundary. Chrome above the stage, including wrapped toolbars, is already reflected in its measured top. A Context Panel below the host is included as trailing shell space; a side rail is not incorrectly subtracted from height. No application-owned DOM is traversed or resized internally.

The positioned Aperture dock normally fits in the existing host padding. If its measured height and bottom offset require more room, additional padding is reserved below the managed task row, preserving the existing dock and toolbar presentation. Sizing subtraction uses iframe layout-viewport coordinates throughout: visual viewport offset plus height, minus the stage DOMRect top and trailing shell space. Iframe document scroll can expose more space above the stage; outer Studio document scrolling is not read. Document-coordinate metrics are diagnostic only. The resulting stage client dimensions, excluding its border, are passed to the geometry model.

While managed mode is active, default minimum-height floors on the shell and relevant layout containers are temporarily relaxed; any explicit shell-region minimum is honored. Prior inline values and priorities for minimum heights, measured stage height and managed-canvas padding are restored when leaving managed mode. There is no global body flex conversion, page overflow lock, Context Panel collapse or preview CSS change. Application content continues scrolling inside the existing managed body.

A soft 180px stage minimum keeps window controls usable when shell chrome alone exhausts a short viewport. A genuinely smaller bounded host takes precedence. Necessary page scrolling can therefore remain in small previews or when the unchanged Context Panel occupies substantial space. Completely hidden, zero-width or collapsed bounded hosts defer initialization/fitting rather than generating 1px window geometry. Open requests can wait for reactivation. A 300px initial CSS fallback is used only before measurable browser layout is available.

ResizeObserver watches the stage and shell ancestors/siblings, not application internals. Notifications are coalesced through requestAnimationFrame, height writes occur only when the result changes, and fitting/painting occurs only when bounds change. Iframe document scroll, browser/visual-viewport resize, visual-viewport scroll and normal shell render/configure paths also measure. Zero-height visual viewports defer measurement instead of falling back to a larger layout viewport. Observer subscriptions are replaced only when the shell path changes. CSS visibility-only changes without a resize must use the normal shell decoration/reactivation path. Read-only ScopeManagedWindows.measure() exposes the last sizing budget for diagnostics, without an operator-facing panel.

Initial sizing and restore semantics

A new first managed window opens in normal state, centered with a nominal 16px gutter where space permits. It starts from the application's existing preferred dimensions and uses 75% of any additional available width/height. When space is smaller than the preference, only its displayed rectangle is constrained; its intended size retains the application preference for later enlargement. Existing saved initialized layouts are never reinitialized to this policy. Later window launches and explicit cascade/reset arrangements remain bounded, with the existing application size profiles. Browser Pop Out requests continue using the unchanged legacy non-fullscreen initial-size path.

restore now represents intended normal geometry; rect is the current constrained display rectangle. Fit operations derive the latter without shrinking the former. Enlarging a workspace therefore recovers the prior dimensions/position where possible. A deliberate move updates intended position while retaining a temporarily constrained size. A deliberate resize establishes a new intended rectangle. Maximize, docking, minimize/reopen and close/reopen preserve normal intent; explicit Restore returns to that intent under current bounds. These operations never alter application state.

Tile adds optional tile:{column,row,columns,rows} placement metadata to each tiled window, allowing cells to remain proportional and non-overlapping while the grid fits. If shrinking would make cells smaller than usable window minima, rendered windows temporarily cascade without discarding their tile intent; enlargement restores the grid. Maximize/dock/restore can retain the tile placement; a manual move/resize or Cascade leaves it. Existing JSON without this optional field remains valid, and design schema version remains 1. Current Studio and newly generated standalone runtimes accept and export it. Older exported HTML must be regenerated to understand the new optional placement metadata and sizing logic.

Phase B verification corrections

Review began from clean checkpoint 1433d40. The previous formula subtracted a document-relative stage top (rect.top + scrollY) from a layout-viewport-relative lower edge. This understated the available height by the iframe document scroll offset. The correction uses viewportBottom - rect.top - reserve. Ancestor rectangle differences already use matching coordinates and need no conversion. Neither a parent-page offset nor the existing Studio Scale transform is mixed into iframe-local sizing.

The corrected regression intentionally replaces the previous incorrect invariant: with supplied 900px viewport, stage top 216px and trailing space 143px, a 120px iframe scroll gives top 96px and stage height 661px rather than 541px. With visual viewport offset 40px and height 600px, the same supplied scrolled rectangles give 401px. These are controlled test calculations, not rendered-browser measurements.

Cleanup previously restored only ancestor minimum heights while leaving measured inline height/padding on cached managed nodes. All three sizing properties now share exact value/priority capture and restoration. Identical measurements and decoration no longer perform redundant sizing-style writes. Queued callbacks cannot reapply overrides after deactivation. Tests track observer subscriptions, coalesce 20 notifications into one queued calculation and verify convergence after a height-changing callback. No additional host-bound or intended-geometry defect was identified in the covered cases; workspace.js is unchanged by this verification correction.

Expanded tests cover nonzero iframe scroll, cross-origin parent isolation, visual viewport pan/resize and zero height, shrink/enlargement, toolbar wrapping, Command Deck context-row transitions, supplied Guided/Advanced iframe budgets, managed activation/deactivation, priority restoration and multiple arrangements. The preview-budget cases do not render the outer Studio grid or change Scale behavior. Native browser access remained unavailable during this verification correction.
