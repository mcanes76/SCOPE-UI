SCOPE Display Map-Centric Layout

Change requested on feature/scope-app-integration after checkpoint 5bbcf40. The initial working tree was clean. This change explicitly updates the Display mockup's owned interface and its Window Manager sizing preference; it does not implement production application integration or introduce Visual Families.

Inspection and control inventory

The active implementation is the regional DisplayModule.render override in mockups/scope-integrated-electric-glass.html, following the texture renderer. The earlier orthographic implementation remains a historical base used by existing legacy tests. Only the active regional presentation is changed.

Previously, nine wide camera buttons, three checkboxes and a simulation paragraph preceded the map. The map retained a 500:390 aspect ratio regardless of available application height. A legend, selected-node details, ten node shortcut buttons and attribution followed it. This placed primary node selection below unrelated sections and consumed significant vertical space. The Display preferred managed size was 820×560.

Layout and ownership

Display CSS is confined to its app host, generic application wrapper containing that host and new Display-owned classes. No Display selector references managed-window classes, no code queries Window Manager internals, and no shell code reaches into Display controls. The application wrapper and host allocate remaining height to the Display root; tabs and its compact command row take their natural height, and the map takes the remainder. Raw demo pages retain a natural 420px application minimum; bounded Studio hosts can shrink. UI-details-hidden mode still leaves compact application tabs visible.

The camera, texture resampling, regional projection, nodes, link models, selection semantics and action algorithms are unchanged. Canvas and SVG share the original coordinate aspect ratio; CSS uses contain fitting to preserve overlay alignment when the outer map viewport changes shape. Letterboxing can occur instead of stretching geographic data. Disclosure open state is transient and kept in an application-owned WeakMap per view, so checkbox refreshes do not close Layers. It is not added to the portable view or design schema.

The Window Manager's Display preference is now 1120×560, instead of 820×560. Only its preferred width changes. Existing initial-size scaling, boundary fitting, minimum dimensions, operator geometry, caching, docking, tile/cascade, minimize/restore/maximize and browser pop-outs remain unchanged. Other applications retain their original size profiles. Very constrained hosts may depart from the preferred aspect ratio; primary controls remain compact and secondary content scrolls deliberately.
