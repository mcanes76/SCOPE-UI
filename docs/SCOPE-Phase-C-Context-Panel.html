Phase C: shared shell Context Panel

Implemented in d371e5b for the Studio and standalone prototypes. The panel is shell-owned and independent of the application simulations. See Phase B host sizing and Phase D preview sizing for the surrounding layout behavior.

Behavior and compatibility

One shell-owned panel contains the original Demonstration inventory and Navigation summary. It is shared by Aperture, Mosaic, Portal and Command Deck, including Single Application, Two Applications, Stacked and Managed Windows. An accessible Show/Hide Context Panel button lives in the existing workspace toolbar, with aria-expanded, aria-controls, native keyboard activation and retained focus during decoration.

The panel is reparented across shell renders rather than duplicated per application. Existing shell nodes are moved into a shared main track without cloning or remounting applications when visibility changes. Hiding removes its grid allocation; existing responsive behavior places it below the workspace at widths up to 1250 pixels. Context contents scroll independently with a 75vh limit, retaining scroll position and shell event history. Explicit Context visibility takes precedence over the application demo-details switch, which continues to govern application details.

New designs default to collapsed in Studio and in newly exported standalone mockups made from that default. Existing schema-1 JSON with explicit visibility preserves that choice; legacy JSON omitting the field retains the original open default. Existing regional hidden overrides remain effective until an operator or editor explicitly reopens the panel. Reopening preserves width and styling overrides. Visibility is stored as layout.contextVisible. A regions.context.visible override can also hide it. Studio changes participate in Undo/Redo, candidates and design JSON export. Standalone changes can be saved via Export Current SCOPE Design or Save Updated Mockup. Exported CSS captures visibility styling. JSON or HTML preserves the setting for later reuse.
