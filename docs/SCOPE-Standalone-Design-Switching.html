Standalone SCOPE Design JSON Switching

Generated standalone operator Mockups can load, switch, export and restore shell designs without returning to Design Studio. They reuse the existing design schema version 1, validator, token compiler and configuration-application mechanism. No server, external runtime, network access, Python or Node.js is required to use these controls.

Regenerate older exported HTML files. Existing offline files contain their old runtime and do not gain controls automatically. Rebuild the Studio distribution and export a new standalone Mockup or configurable folder. Old Design Studio scope-design.json files remain usable if they conform to the supported version 1 schema and embedded preset catalog. Existing sample/export HTML files elsewhere in the repository are not overwritten by this feature.

Applications and Phase 3 windows

  • Design import never reloads the page or resets application-owned stores. Existing managed application DOM and uncommitted input survive appearance/navigation changes. Each application continues to have at most one cached managed instance.
  • Imported geometry is fitted to the available workspace. Existing open managed applications are retained even if the imported design omits them or marks them closed/minimized. The exported active design reflects this preserved live arrangement rather than pretending those applications were closed.
  • Switching to a classic single/split/stacked arrangement parks managed DOM instead of closing it. The UI explicitly explains how to return with Managed Windows. Classic hosts can rebuild and reset transient focus/scroll; existing per-slot view maps and application data remain. Different layouts may show their previous per-slot view selection.
  • Finish or cancel an application dialog, simulated loading operation or window drag before switching. Unsafe transitions are rejected before mutation, with instructions to retry. A design requesting an application disabled by current parameters is also rejected; enable that application through Parameters JSON or choose another design.
  • A shell-managed application window is an in-page frame controlled by Phase 3. A browser pop-out is a separate browser/OS window containing one application and an independent simulation. A pop-out applies appearance/navigation changes while retaining that one application; it does not become a multi-application desktop. Its UI reports this adaptation.
  • Authenticated parent design-switch messages preserve a pop-out's independent application parameters. If that pop-out is busy, its design update is skipped and explained locally. Existing ordinary parameter/design propagation otherwise retains its previous behavior.

Validation and errors

The importer requires a version 1 design document with navigation and theme, validates it using ScopeDesign.validate, and preflights the shared CSS compiler. Unknown design/style fields, unrecognized nested parameter presentation fields and unsupported versions/presets are rejected. Numeric normalization follows the existing schema. Parameter fields intentionally preserved from the active Mockup are explicitly identified in the success message; they are not silently applied to the applications.

Wrong-type messages direct a design mistakenly chosen as Parameters JSON to Import SCOPE Design JSON, and Parameters JSON mistakenly chosen as a design to Import Parameters JSON. Malformed JSON is rejected. Design files are limited to 6 MiB; existing parameter/image limits remain. Invalid imports leave the active design untouched. The original snapshot is cloned so imports and resets cannot mutate it.

Native browser limits: Chrome was observed loading the generated Mockup A directly from file://, with application content and Phase 3 window controls present. Concurrent user input/tab changes prevented completing the interactive import/export/reset sequence without interfering with the user's browser. Edge was launched, but its test window became unavailable after an optional setup prompt, before a Mockup could be tested. Edge and full native interactive switching are not claimed as verified. Use the temporary A/B files to finish manual testing in each target browser, including file dialogs, Save As/download behavior, resets, pop-outs and transient focus/scroll. Automated controlled DOM results do not establish native browser rendering or file-dialog behavior.
