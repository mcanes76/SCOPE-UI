One canonical palette ID

The design's theme is the canonical palette ID. Each entry in design-studio/theme-presets.json declares its family, light/dark mode, roles, geometry and typography. Family is derived from that entry, preventing contradictory family/palette combinations. The preview sets body[data-theme]; legacy data-look supplies retained structural materials only. New palette activation never depends on an old engine-look selector.

It uses compact 14px system typography, 6px controls and 10px panels. SCOPE retains its existing simulation behavior, globe, topology models and semantic action colors; the reference code is not executed or bundled. Source filename and SHA-256 are recorded in the preset metadata.

visual-system.js resolves page, shell, navigation, workspace, panel, raised/inset surfaces, text roles, borders, selection/focus and interactive states. The same compiler styles actual application bodies, forms, tables, dialogs and controls. Green Join/Enable, red Leave/Disable, yellow Warning and purple Configuration retain semantic tokens independent of decorative accents.

Component inheritance

Family default→ Palette→ Global / component class→ Application→ Instance

In Advanced mode open Component styles & button geometry. Select global, category/class, application or instance scope. Supported classes include buttons, semantic button categories, headers, panels, tab bars, navigation and window frames. Edit fill, text/icon colors, border width/style/color, radius and individual corners, padding, control height, font, elevation and interaction-state colors.

Pick a button in preview enters an explicit selection mode. The selection click is intercepted before the application action runs. Otherwise application controls operate normally. Instance IDs derive from application, action and occurrence within the current view; changing a repeating list may change occurrence-based identity, so verify instance styling after data/list changes. Class or application overrides are more stable for repeated rows.

Reset to Inherited Style deletes only that scope's override. Appearance fields never replace event handlers or change simulated operations. Intentional fill/text overrides show semantic/contrast guidance; labels and status symbols remain present. User overrides can still produce poor contrast: inspect them on the target display.

  "theme": "slate-light",
  "components": {

    "classes": { "configuration": { "borderStyle": "dashed" } },
    "applications": { "blos": { "buttons": { "fontSize": 16 } } },
    "instances": { "blos:group-join:0": { "radius": 12, "border": "#17613F" } }
  }
}

Design schema 1 remains backward compatible through optional components, parameters and operator extensions. Old designs receive inherited defaults. Unknown control properties, arbitrary CSS, invalid IDs and unsupported versions are rejected. Numeric dimensions are bounded. Undo/Redo and candidate snapshots include these fields.

Operator windowing belongs to the mockup

The operator toolbar ships in the preview and every exported mockup. It provides Single Application, Two Applications, left/right application selectors, Pop Out, Return to Main Workspace and Component Laboratory. The shell's normal navigation remains usable. The generic demonstrations remain separate from application workspaces.

Closed windows can be reopened. A blocked pop-up produces feedback and leaves split view usable. Multiple-window placement remains browser-controlled.

Detached application data models remain independent in both file and HTTP editions. Shared simulated-data synchronization is not implemented; it would require an explicit store import/replication contract to avoid duplicate operations. Design changes use source/origin-checked window messages with per-window tokens. No BroadcastChannel model synchronization is claimed. Application UI state at launch is copied where feasible; pending asynchronous operations and later edits are not live-shared.

Versioned parameters without rebuilding Studio

Use design-studio/params.example.json and params.schema.json. Runtime validation is implemented by parameters.js. Legacy presentation parameters with no version or version 1 migrate to version 2 with defaults; future versions are rejected. Stable application IDs remain blos, display, calibration, los.

{
  "schemaVersion": 2,
  "branding": { "name": "Customer Console" },
  "logoPath": "assets/logo.png",
  "applications": { "blos": { "name": "Regional Links", "visible": true } },
  "labels": { "shells": { "deck": "Operator Deck" } },
  "initial": {
    "theme": "slate-light", "navigation": "deck", "mode": "split",
    "left": "blos", "right": "display"
  },
  "allowedModes": ["single", "split", "popout"],
  "buttonGeometry": "slight"
}

Application tabs configures internal tab names. At least one application must stay visible; initial applications must be visible. The initial mode must be allowed. Palette ID determines the initial family. Relative logo paths are intended for the folder edition. In standalone use, Import Logo Image embeds image bytes; configured missing/relative logos fall back to the embedded crosshair/default. Image aspect ratios are preserved.

Studio Advanced/Final Review also exposes branding and name fields. Application and navigation renaming changes presentation labels, not model identities or behavior.

Component-library assessment

Emil Kowalski's pick-ui-library guidance was reviewed against the existing stack. The repository has native HTML controls and no React dependency. shadcn/ui is a useful future React component foundation, and Sonner targets React toast notifications. A migration solely for those controls would add framework/build/runtime cost to the portable artifact. Native selects, dialogs, file inputs, live status regions and focus styles are retained. Magic UI enhancements are not needed for this operator/workshop tool; no decorative animation library was added. Reduced-motion rules disable optional transitions/animations.

Palette references: Carbon role-based layering, Radix scale roles for surfaces and states, and USWDS neutral and accent roles. SCOPE uses original coordinated values inspired by these approaches.

Actual Chrome/Edge visual, keyboard/pointer, native file/download, pop-up, PDF and file:// tests were unavailable because no browser surface was exposed. Controlled JavaScript fixtures are not browser acceptance evidence. DISCO source-token and material checks use the supplied BLOS v11 reference; rendered browser fidelity still requires visual review.
